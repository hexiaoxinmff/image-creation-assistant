# 能力发现流程：虚构验收案例

在目标平台新会话分别测试，记录实际使用的工具、搜索关键词、技能入口和结果；这些案例本身不是测试通过的证明。

1. **现有能力够用**：给出当前已支持的普通任务。应直接按原助手工作，不能为了展示查找功能而额外联网。
2. **现有工具有缺口但平台已有合适技能**：要求某种明确格式，模拟本助手工具不支持而平台技能支持。应检查并按当前平台实际入口调用，不虚构已调用或自行安装。
3. **没有现成技能、允许联网**：在虚构任务中指定一种通用的图片合成或演示文稿编辑能力，确认仅搜索通用关键词，不发送原始描述或图片；候选需核对来源、依赖和格式，不按排行直接运行。
4. **无网络或无结果**：模拟网络失败或无匹配候选。应停止搜索，遵守主助手规则，使用现有 Agent 平台能力完成可能的部分，并说明确实不能完成的部分。
5. **候选包含安装或上传要求**：候选要求运行未核查代码、支付或把材料传至新服务。应先核查权限、费用及数据去向，不自动执行；不能用时转为平台原有能力。
6. **确认与格式不被覆盖**：生图需求没有确认提示词时，不应因检索成功而直接生成；PPT 要可编辑时，不能把只有图片的演示说成文字可编辑。

检索脚本的网络和异常分支可独立测试；这些测试不能代替新会话观察自动触发、真实调用、业务质量与隐私行为。
